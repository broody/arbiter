# Cairo: arbiter_dojo and arbiter_adapter

`arbiter_dojo` binds the [channel state machine](/reference/cairo#the-channel-module) to a Dojo world: models, an event, and one helper per entrypoint of a game system. `arbiter_adapter` is the logic of a proof adapter, the account contract that proves a replay and hands the result to the channel. This page lists both crates' public items. For a walkthrough, see [Deploy the channel](/guide/channel) and [Add a proof adapter](/guide/adapter).

| Crate | Path | Toolchain |
| --- | --- | --- |
| `arbiter_dojo` | [`dojo/arbiter_dojo`](https://github.com/broody/arbiter/blob/main/dojo/arbiter_dojo/src/lib.cairo) | Cairo 2.13.1, Dojo 1.8.0. The `dojo/` workspace builds it with the counter example. |
| `arbiter_adapter` | [`adapter/arbiter_adapter`](https://github.com/broody/arbiter/blob/main/adapter/arbiter_adapter/src/lib.cairo) | Cairo 2.18.0, for execution-info v3 proof facts. The `adapter/` workspace builds it with the counter example. |

## arbiter_dojo models

`arbiter_dojo::models` ([`models.cairo`](https://github.com/broody/arbiter/blob/main/dojo/arbiter_dojo/src/models.cairo)). A game registers the models and the event in its namespace through `build-external-contracts` (see [Wrapping the helpers](#wrapping-the-helpers)).

A channel is stored in two models: `ChannelTerms`, written once, when `open_game` opens the game, and `ChannelState`, four felts written on every transition. A game that takes its randomness from its referee has a third, `ChannelRng`. `ChannelGame` is not a model: it is the combined view that `read` builds and a game's `get_channel` returns.

### ChannelGame

One arbiter channel: its terms and its state together. Derives `Copy`, `Drop`, `Serde`, `PartialEq` and `Debug`. Seats are in the terms' order.

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | `felt252` | Game id, chosen by the clients and named in the terms. |
| `player_0`, `player_1` | `ContractAddress` | Each seat's wallet. |
| `key_0`, `key_1` | `felt252` | Session public keys. |
| `tip_0`, `tip_1` | `felt252` | Committed hash-chain tips. |
| `prover` | `ContractAddress` | The game's proof adapter. |
| `config` | `Span<felt252>` | The game's `Config`, serialized. |
| `status` | `u8` | Channel status (`arbiter::channel::ACTIVE` ... `SETTLED`). A game nobody opened has no `ChannelGame`: `read` panics. |
| `epoch` | `u32` | Channel epoch. |
| `context` | `felt252` | `context_hash` of the terms. |
| `response_seconds` | `u32` | Window length. |
| `referee` | `felt252` | A timed game's referee key; zero for an untimed game. |
| `clock_settings` | `Span<felt252>` | A timed game's `TimeControl.settings`; empty for an untimed game. |
| `referee_tip` | `felt252` | A timed game's `TimeControl.rng_tip`: the tip of the referee's hash chain when the game takes its randomness from the referee, otherwise zero. |
| `anchor` | `StoredRef` | The committed state. |
| `candidate` | `StoredRef` | The best dispute candidate. |
| `anchor_block` | `u64` | Block of the last anchor change or resume. |
| `candidate_block` | `u64` | Block the candidate was set in. |
| `deadline` | `u64` | End of the current window, or 0. |
| `acked_epoch`, `acked_deadline` | `u32`, `u64` | The dispute (epoch and deadline) the referee acknowledged. |
| `result` | `StoredOutcome` | The final result once settled. |
| `started` | `u64` | When the game started, in seconds: the first stamp (`Clock.started`) of any state the channel received, as its referee attests it. 0 for an untimed game and until such a state arrives. A rated game takes its time from it. |

`referee`, `clock_settings` and `referee_tip` form the game's `TimeControl`. The channel fields mirror `arbiter::channel::Channel` ([Channel](/reference/cairo#stateref-and-channel)).

| Function | Behavior |
| --- | --- |
| `channel_of(game: @ChannelGame) -> Channel` | The channel fields as a `Channel`. |
| `with_channel(game: ChannelGame, channel: Channel) -> ChannelGame` | `game` with its channel fields replaced by `channel`'s. |
| `game_of(terms: @ChannelTerms, channel: Channel, referee_tip: felt252) -> ChannelGame` | The combined view: the terms, the unpacked channel, and the referee's tip (zero for a game without one). |
| `pack_state(id: felt252, channel: @Channel) -> ChannelState` | Packs a channel (below). Panics with `'Value exceeds 40 bits'` if `deadline`, `anchor_block`, `candidate_block` or `acked_deadline` is `2^40` or more, and with `'Value exceeds 34 bits'` if `started` is `2^34` or more. |
| `unpack_state(state: @ChannelState, context: felt252, response_seconds: u32) -> Channel` | Unpacks a channel. `context` and `response_seconds` live in `ChannelTerms`, so the caller passes them. |

### ChannelTerms

What a channel fixes when it opens. `#[dojo::model]`, keyed by `id`. `open_game` writes it once; a non-zero `player_0` is what marks a game id as open.

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | `felt252` (key) | Game id. |
| `player_0`, `player_1` | `ContractAddress` | Wallets, as in `ChannelGame`. |
| `key_0`, `key_1` | `felt252` | Session public keys. |
| `tip_0`, `tip_1` | `felt252` | Committed hash-chain tips. |
| `prover` | `ContractAddress` | The game's proof adapter. |
| `config` | `Span<felt252>` | The game's `Config`, serialized. |
| `context` | `felt252` | `context_hash` of the terms. |
| `response_seconds` | `u32` | Window length. |
| `referee` | `felt252` | Referee key; zero for an untimed game. |
| `clock_settings` | `Span<felt252>` | Serialized time settings; empty for an untimed game. |

### ChannelRng

The referee's randomness for a channel whose terms take it. `#[dojo::model]`, keyed by `id`. Only such a game has one: `open_game` writes the tip the referee signed. `ChannelState` says which games have one (`referee_rng`), so a game whose seats reveal to each other never reads or writes it. `read` and `get_channel` return the tip as `ChannelGame.referee_tip`.

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | `felt252` (key) | Game id. |
| `tip` | `felt252` | The tip of the referee's hash chain. |

### ChannelState

The channel state machine's fields in four felts. `#[dojo::model]`, keyed by `id`. Every transition reads and writes it; clients read the `ChannelUpdated` event or `get_channel` instead.

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | `felt252` (key) | Game id. |
| `anchor` | `felt252` | The anchor's hash. |
| `candidate` | `felt252` | The candidate's hash, or zero while it equals the anchor's. |
| `times` | `felt252` | Status, epoch, deadline, blocks and the acknowledgement, packed. |
| `refs` | `felt252` | Both references' small fields and the result, packed. |

`pack_state` lays out `times` and `refs` as follows, from bit 0:

| Word | Bits | Field |
| --- | --- | --- |
| `times` | 0..8 | `status` |
| | 8..40 | `epoch` |
| | 40..80 | `deadline` |
| | 80..120 | `anchor_block` |
| | 128..168 | `candidate_block` |
| | 168..200 | `acked_epoch` |
| | 200..240 | `acked_deadline` |
| | 240 | `referee_rng` |
| `refs` | 0..89 | The anchor's reference |
| | 89..106 | `result` |
| | 128..217 | The candidate's reference |
| | 217..251 | `started` |

A reference (89 bits) is `seq` (bits 0..32), `support_turn` (32..64), `due` (64..72) and its outcome (72..89). An outcome (17 bits) is `finished` (bit 0), `winner` (1..9) and `reason` (9..17). Blocks and timestamps get 40 bits each, which lasts for millennia. `started` gets 34, which lasts until 2514: a felt's high word holds 123 bits, and `refs` fills it.

### ProverAllowed

Proof adapter classes the namespace owner accepts. `#[dojo::model]`.

| Field | Type | Meaning |
| --- | --- | --- |
| `class_hash` | `felt252` (key) | Adapter class hash. |
| `allowed` | `bool` | Whether channels accept provers of this class. |

### Stored types

Storable (`Introspect`, `DojoStore`) mirrors of the core types, with `Into` conversions both ways. `ChannelGame` uses them for its references and result.

| Type | Mirrors | Fields | Conversions |
| --- | --- | --- | --- |
| `StoredOutcome` | `Outcome` | `finished`, `winner`, `reason` | `OutcomeIntoStored`, `StoredIntoOutcome` |
| `StoredRef` | `StateRef` | `hash`, `seq`, `support_turn`, `due`, `outcome: StoredOutcome` | `RefIntoStored`, `StoredIntoRef` |

### ChannelUpdated

A `#[dojo::event]` emitted by every helper that writes a channel's state.

| Field | Type | Meaning |
| --- | --- | --- |
| `game_id` | `felt252` (key) | The game. |
| `kind` | `u8` | Which helper wrote it (below). |
| `epoch` | `u32` | Channel epoch after the write. |
| `seq` | `u32` | `seq` of the reported state. |
| `status` | `u8` | Channel status after the write. |
| `deadline` | `u64` | Channel deadline after the write. |
| `state_hash` | `felt252` | Hash of the reported state. |
| `winner`, `reason` | `u8` | The result when settled, otherwise the reported state's outcome. |

The reported state is the candidate while the channel is in `DISPUTE`, and the anchor otherwise.

| `kind` constant | Value | Emitted by |
| --- | --- | --- |
| `OPENED` | `0` | `open_game` |
| `DISPUTED` | `3` | `open_dispute` |
| `RECEIVED` | `4` | `accept_verified`, `submit_history` |
| `RESOLVED` | `5` | `resolve` |
| `FORCED` | `6` | `force` |
| `RESUMED` | `7` | `resume`, `resume_by_referee` |
| `TIMED_OUT` | `8` | `claim_timeout` |
| `RESIGNED` | `9` | `resign` |
| `ACKNOWLEDGED` | `10` | `acknowledge` |
| `ROLLED` | `11` | `roll` |
| `VOIDED` | `12` | `void` |

:::warning
`kind` values are not channel statuses. `models::FORCED` is 6, while the status `arbiter::channel::FORCED` is 3, and `OPENED` is 0, the value of the status `UNOPENED`. Read `status` for the channel's status.
:::

Kinds 1 and 2, once a join and a cancel, are retired: a game opens once, on every seat's signed terms.

## arbiter_dojo helpers

`arbiter_dojo::channel` ([`channel.cairo`](https://github.com/broody/arbiter/blob/main/dojo/arbiter_dojo/src/channel.cairo)). Each helper wraps a transition of `arbiter::channel` with storage, caller authentication, prover checks and signature checks, then saves the channel's state and emits `ChannelUpdated`. Generic helpers take the game's rules, e.g. `open_game::<MyRules>(ref world, ...)`; trait bounds are omitted below.

"Caller" is `get_caller_address()` inside the game system, so the wallet that called it. "Now" and "block" are the block timestamp and number.

Helpers that read the channel's terms first panic with `'Unknown channel'` for a game nobody opened: `accept_verified`, `submit_history`, `open_dispute`, `force`, `roll`, `claim_timeout`, `resign`, `snapshot` and `read`. The others read only the packed state, which is all zeros (`UNOPENED`) for a game nobody opened, and fail on its status or its zero referee key instead; `result` returns `None` and `status` returns `0`.

### Who may call

| Caller | Helpers |
| --- | --- |
| A player (`seat_of` the caller) | `open_dispute`, `force`, `claim_timeout`, `resign` |
| Anyone | `open_game`: authenticated by every seat's wallet signature over the terms, and the referee's signature over its tip when the game takes its randomness. `submit_history`, `resolve`, `resume`: authenticated by signatures and the channel's windows, not by the caller. `acknowledge`, `resume_by_referee`: authenticated by the referee's signature. `roll`: authenticated by the referee's hash chain. `void`: authenticated by every seat's signature, or allowed once the pause has run out. |
| The game's prover | `accept_verified` |
| A namespace owner | `allow_prover` |
| Read-only | `terms`, `snapshot`, `result`, `read`, `read_state`, `status`, `seat_of` |

### Opening a game

```cairo
fn open_game<impl R: GameRules>(
    ref world: WorldStorage, terms: Terms<R::Config>, signatures: Span<Span<felt252>>,
    referee_signature: Signature,
);
```

`open_game` opens a game on its seats' signed terms. Anyone may send it, usually in one transaction with the first call that needs the chain: a settlement (`submit_history`, or the adapter's `settle`), or a player's dispute, resignation or timeout claim. `signatures` holds each seat's wallet signature over the terms, in seat order, each the felt array its wallet returned. `referee_signature` is the referee's over its randomness tip when the terms take the referee's randomness, otherwise zero. It checks, in order (panic):

1. `terms.chain_id` is the transaction's chain id (`'Wrong chain'`), and `terms.channel` is the game system's own address (`'Wrong channel'`).
2. `terms.game_id` is non-zero (`'Invalid game id'`) and no channel holds it yet (`'Game already open'`). Clients choose the id.
3. `open(terms)` builds the opening state (any [`open` panic](/reference/cairo#envelope-and-seats): `'Wrong tip count'`, `'Invalid tip'` for a zero tip, `'Invalid referee'` and any panic of the game's `ClockRules::check`, such as `StandardTime`'s `'Invalid time control'`, and any `R::init` panic for an invalid config).
4. Two players and two keys (`'Wrong seat count'`), and two signatures (`'Wrong signature count'`).
5. The players are non-zero and differ (`'Invalid players'`).
6. Each session key is non-zero and the x coordinate of a curve point (`'Invalid session key'`), and the keys differ (`'Shared session key'`): one signature would approve for both seats.
7. The tips differ (`'Invalid tip'`).
8. The prover is non-zero (`'Zero prover'`) and its class is allowed (`'Untrusted prover class'`).
9. In a timed game, the referee key is valid (`'Invalid session key'`) and neither seat's (`'Referee is a seat'`).
10. The referee's tip (below).
11. Each seat's wallet accepts its signature: the helper calls `is_valid_signature(terms_message(chain_id, game_id, context, player), signature)` on the player's account, which must answer `'VALID'` or `1` (`'Invalid wallet signature'`). The account must be deployed.
12. `channel::open`: the response window is in range (`'Invalid response window'`).

It then writes `ChannelTerms`, and `ChannelRng` when the game takes its referee's randomness, and an `ACTIVE` state at epoch 0 whose anchor and candidate are `state_ref(open(terms))` at the current block, and emits `OPENED`.

| The terms' time control | `open_game` requires (panic) |
| --- | --- |
| Takes the referee's randomness (a non-zero `clock.rng_tip`) | `referee_signature` the referee's signature over `tip_hash(chain_id, channel, game_id, rng_tip)`, with the transaction's chain id and the game system's address (any `verify` panic, such as `'Invalid session signature'`). |
| A zero `rng_tip`, or an untimed game | A zero `referee_signature` (`'Seats reveal in this game'`). |

The signature is what keeps a seat from choosing the tip: a tip a seat made up would let that seat know every roll. It names the game, so a tip signed for one game is refused in another.

### Submitting states

```cairo
fn accept_verified<impl R: GameRules>(
    ref world: WorldStorage, game_id: felt252, epoch: u32, start_hash: felt252,
    end: Envelope<R::State>, acks: Span<Signature>,
);
fn submit_history<impl R: GameRules>(
    ref world: WorldStorage, game_id: felt252, epoch: u32, start: Envelope<R::State>,
    witness: R::Witness, batch: Batch<R::Action>, acks: Span<Signature>,
);
```

Both start from the anchor or from the candidate, and end in `arbiter::channel::receive`. Starting from the candidate extends it, so a long transcript can arrive in segments within one dispute window. `acks` holds one signature per seat over `checkpoint_hash(context, epoch, state_hash(end))`: all zeros submits without approval (the state becomes a dispute candidate), otherwise every seat's signature must verify (`'Wrong approval count'`, `'Invalid session signature'`, ...) and the state commits at once. See [Settlement and proofs](/concepts/settlement).

| Helper | Checks (panic) | Effect |
| --- | --- | --- |
| `accept_verified` | Caller is the game's `prover` (`'Only prover'`) and its class is still allowed (`'Untrusted prover class'`); `start_hash` equals the anchor's or the candidate's hash (`'Wrong proof anchor'`); then `receive`'s checks. | Receives `end`, which the adapter proved replays from `start_hash`. |
| `submit_history` | `state_hash(start)` equals the anchor's or the candidate's hash (`'Wrong anchor state'`); `replay` from `start` with the stored context and terms (every [replay panic](/reference/cairo#replay)); then `receive`'s checks. | Replays `batch` onchain, without a prover, and receives the end state. |

### Disputes and forced play

```cairo
fn open_dispute(ref world: WorldStorage, game_id: felt252, epoch: u32);
fn acknowledge<impl R: GameRules>(ref world: WorldStorage, game_id: felt252, epoch: u32, signature: Signature);
fn resolve(ref world: WorldStorage, game_id: felt252, epoch: u32);
fn force<impl R: GameRules>(
    ref world: WorldStorage, game_id: felt252, epoch: u32, start: Envelope<R::State>,
    witness: R::Witness, steps: Span<Move<R::Action>>,
);
fn roll<impl R: GameRules>(
    ref world: WorldStorage, game_id: felt252, epoch: u32, start: Envelope<R::State>,
    witness: R::Witness, value: felt252,
);
fn void<impl R: GameRules>(ref world: WorldStorage, game_id: felt252, epoch: u32, acks: Span<Signature>);
fn resume<impl R: GameRules>(ref world: WorldStorage, game_id: felt252, epoch: u32, acks: Span<Signature>);
fn resume_by_referee<impl R: GameRules>(ref world: WorldStorage, game_id: felt252, epoch: u32, signature: Signature);
fn claim_timeout(ref world: WorldStorage, game_id: felt252, epoch: u32);
fn resign(ref world: WorldStorage, game_id: felt252);
```

| Helper | Checks (panic) | Effect |
| --- | --- | --- |
| `open_dispute` | Caller is a player (`'Not a player'`); then `channel::open_dispute`. | Opens a dispute from the anchor. |
| `acknowledge` | The game is timed (`'Untimed game'`); `signature` is the referee's over `live_hash(context, epoch, deadline)`, with the channel's current deadline (any `verify` panic); then `channel::acknowledge` (`'No dispute'`, `'Stale channel epoch'`, `'Dispute window closed'`). | Records that the referee is live during this dispute, so `resolve` returns an unfinished game to offchain play instead of forced play. The status does not change. |
| `resolve` | `channel::resolve` (`'No dispute'`, `'Stale channel epoch'`, `'Dispute window open'`), with `timed` true when the game has a referee key. | Commits the candidate: settles a finished game; otherwise returns an acknowledged timed game to `ACTIVE` and starts forced play for any other. Forced play starts paused when the candidate waits for the referee's roll. |
| `force` | Caller is a player; `state_hash(start)` equals the anchor hash (`'Wrong anchor state'`); `arbiter::force` with the caller's seat (`'Not your step'` and any step panic); then `channel::forced` (`'Not your turn'`, `'Turn deadline passed'`, ...). | Applies the caller's steps onchain. The wallet call authenticates them instead of signatures. They carry no stamps, so a timed game's clock pauses. If they end on a request for the referee's randomness, forced play pauses for up to `PAUSE_SECONDS` (3 days): no seat is due until the roll. |
| `roll` | `state_hash(start)` equals the anchor hash (`'Wrong anchor state'`); `arbiter::roll` (`'No roll due'`, `'Invalid reveal'` and any step panic); then `channel::rolled` (`'Not in forced play'`, `'Stale channel epoch'`, `'Turn deadline passed'`, ...). | Posts the referee's value for the roll the anchor waits for, during forced play. Anyone may call it: the referee's hash chain vouches for the value, so it needs no signature. The next seat gets a fresh window. |
| `void` | `acks` over `void_hash(context, epoch, anchor.hash)` from every seat, or all zero (`'Wrong approval count'`, any `verify` panic); then `channel::void` (`'Not in forced play'`, `'Stale channel epoch'`, `'No roll due'`, and `'Pause still open'` when `acks` are all zero before the pause's deadline). | Ends a game whose roll waits for a referee that is down, with no result: `SETTLED` with `REASON_VOID`. At once with every seat's approval, or by anyone once the pause has run out. |
| `resume` | `acks` over `reopen_hash(context, epoch, anchor.hash)` from every seat; then `channel::resume` (`'Need every approval'` when `acks` are all zero). | Returns to offchain play from the anchor. |
| `resume_by_referee` | The game is timed (`'Untimed game'`); `signature` is the referee's over `referee_resume_hash(context, epoch, anchor.hash)` (any `verify` panic); then `channel::resume` (`'Not in forced play'`, `'Stale channel epoch'`, `'Turn deadline passed'`). | Returns a timed game to offchain play from the anchor on the referee's signature alone, so a seat can't keep a game onchain by refusing to approve. It also takes back a game paused for a roll, which the referee then gives offchain. |
| `claim_timeout` | Caller is a player; then `channel::claim_timeout` (`'Waiting for the referee'` while the referee owes a roll, `'Only waiting seat'`, `'Turn window open'`, ...). | Settles against the due seat with `REASON_ABANDON`. |
| `resign` | Caller is a player; then `channel::resign` (`'Channel not live'`). | Settles against the caller's seat with `REASON_RESIGN`. |

### Admin and reads

```cairo
fn allow_prover(ref world: WorldStorage, class_hash: felt252, allowed: bool);
fn terms<impl R: GameRules>(game: @ChannelGame) -> Terms<R::Config>;
fn snapshot<impl R: GameRules>(
    world: @WorldStorage, game_id: felt252,
) -> (Terms<R::Config>, u32, felt252, u64, felt252, u64);
fn result(world: @WorldStorage, game_id: felt252) -> Option<Outcome>;
fn read(world: @WorldStorage, game_id: felt252) -> ChannelGame;
fn read_state(world: @WorldStorage, game_id: felt252) -> Channel;
fn status(world: @WorldStorage, game_id: felt252) -> u8;
fn seat_of(game: @ChannelGame, address: ContractAddress) -> u8;
```

| Helper | Behavior | Panics |
| --- | --- | --- |
| `allow_prover` | Writes `ProverAllowed { class_hash, allowed }`. Emits no event. Revoking a class also stops `open_game` and `accept_verified` for games whose prover has that class. | `'Only namespace owner'` unless the caller owns the world's namespace. |
| `terms` | The game's `Terms`: `chain_id` from the transaction, `channel` = the game system's own address, then the stored game id, prover, window, time control (`None` when `referee` is zero, otherwise `referee`, `clock_settings` and `referee_tip` as its `rng_tip`), players, keys, tips and config. | `'Invalid stored config'` if the config does not deserialize. |
| `snapshot` | What the adapter needs to prove from: terms, epoch, anchor hash, anchor block, candidate hash and candidate block. Outside a dispute the candidate is the anchor. | `'Unknown channel'` for a game nobody opened; `'Channel not live'` unless `ACTIVE`, `DISPUTE` or `FORCED`. |
| `result` | `Some(outcome)` once `SETTLED`, otherwise `None`. Games pay rewards from this. Check `reason` before `winner`: a void game (`REASON_VOID`) has `winner` 0 but is not a draw. | |
| `read` | The `ChannelGame` view, from `ChannelTerms` and `ChannelState`. | `'Unknown channel'` if `player_0` is zero: nobody opened the game. |
| `read_state` | The `Channel` alone, from `ChannelState` and the terms' `response_seconds`, without reading the rest of the terms: its `context` reads as zero. | |
| `status` | The channel's status, read from the packed state. | |
| `seat_of` | `0` for `player_0`, `1` for a non-zero `player_1`. | `'Not a player'` for any other address. |

## Wrapping the helpers

A game system exposes one entrypoint per helper, each one line on top of `arbiter_dojo::channel`. From the counter's system ([`dojo/examples/counter/src/lib.cairo`](https://github.com/broody/arbiter/blob/main/dojo/examples/counter/src/lib.cairo)), with the other entrypoints following the same shape:

```cairo
#[dojo::contract]
pub mod channel {
    use dojo::world::WorldStorage;
    use arbiter::{Batch, Envelope, Move, Signature, Terms};
    use arbiter_counter::{Action, Config, Counter, CounterRules};
    use arbiter_dojo::channel as binding;
    use arbiter_dojo::models::ChannelGame;

    #[abi(embed_v0)]
    impl CounterChannelImpl of super::ICounterChannel<ContractState> {
        fn open_game(
            ref self: ContractState,
            terms: Terms<Config>,
            signatures: Span<Span<felt252>>,
            referee_signature: Signature,
        ) {
            let mut world = self.world_default();
            binding::open_game::<CounterRules>(ref world, terms, signatures, referee_signature);
        }

        fn submit_history(
            ref self: ContractState,
            game_id: felt252,
            epoch: u32,
            start: Envelope<Counter>,
            batch: Batch<Action>,
            acks: Span<Signature>,
        ) {
            let mut world = self.world_default();
            binding::submit_history::<
                CounterRules,
            >(ref world, game_id, epoch, start, (), batch, acks);
        }

        fn snapshot(
            self: @ContractState, game_id: felt252,
        ) -> (Terms<Config>, u32, felt252, u64, felt252, u64) {
            let world = self.world_default();
            binding::snapshot::<CounterRules>(@world, game_id)
        }

        fn get_channel(self: @ContractState, game_id: felt252) -> ChannelGame {
            let world = self.world_default();
            binding::read(@world, game_id)
        }

        // accept_verified, open_dispute, acknowledge, resolve, force, roll,
        // void, resume, resume_by_referee, claim_timeout, resign, allow_prover,
        // terms: one call each.
    }

    #[generate_trait]
    impl InternalImpl of InternalTrait {
        fn world_default(self: @ContractState) -> WorldStorage {
            self.world(@"counter")
        }
    }
}
```

The counter's `Witness` is `()`, so it passes `()` where the helpers take a witness. Its `open_game` takes the whole `Terms<Config>`, which carry the config. A game with a real witness takes it as an entrypoint argument.

The entrypoint names matter to other components:

- The proof adapter calls `snapshot(game_id)` and `accept_verified(game_id, epoch, start_hash, end, acks)` by selector, so keep those names, argument orders and the snapshot's six return values.
- The [keeper](/infra/keeper) reads `get_channel(game_id) -> ChannelGame` and `terms`, and sends `open_game`, `submit_history`, `resolve`, `acknowledge` and `resume_by_referee`. It also reads `force` and `roll` calls back from transaction traces. Its config can rename all of these (`entrypoints`).

The game's `Scarb.toml` registers the models and the event in its world, as the counter does ([`dojo/examples/counter/Scarb.toml`](https://github.com/broody/arbiter/blob/main/dojo/examples/counter/Scarb.toml)):

```toml
[[target.starknet-contract]]
sierra = true
build-external-contracts = [
    "dojo::world::world_contract::world",
    "arbiter_dojo::models::m_ChannelTerms",
    "arbiter_dojo::models::m_ChannelState",
    "arbiter_dojo::models::m_ChannelRng",
    "arbiter_dojo::models::m_ProverAllowed",
    "arbiter_dojo::models::e_ChannelUpdated",

```

`m_ChannelRng` is only needed by a game that takes randomness from its referee.

The system also needs write access to its namespace; the counter grants it in `dojo_dev.toml` with `[writers] "counter" = ["counter-channel"]`.

## arbiter_adapter

A proof adapter is an immutable account contract ([`adapter/arbiter_adapter`](https://github.com/broody/arbiter/blob/main/adapter/arbiter_adapter/src/lib.cairo)):

1. **Proving.** Its `__execute__` runs as a zero-fee virtual `INVOKE_V3` that is never broadcast. It reads the channel snapshot, replays the signed steps from the anchor or the candidate with the game's rules, and sends one L2→L1 message committing to the transition. For a game no channel has opened yet, it takes the terms instead and replays from their opening state. A prover proves that execution.
2. **Settling.** A real transaction calls the adapter's `settle` with the proof attached, after `open_game` in the same transaction when the game wasn't open. The network verifies the proof; `settle` checks that the proof facts commit to exactly this transition and calls the channel's `accept_verified`.

The adapter calls the channel through raw syscalls, so it works with any game system that exposes `arbiter_dojo`'s `snapshot` and `accept_verified` entrypoints. See [Settlement and proofs](/concepts/settlement).

### Functions

`arbiter_adapter::prover`, re-exported at the crate root.

```cairo
fn execute<impl R: GameRules>(
    channel: ContractAddress, game_id: felt252, epoch: u32, start: Envelope<R::State>,
    witness: R::Witness, batch: Batch<R::Action>, opening: Option<Terms<R::Config>>,
);
fn settle<impl R: GameRules>(
    channel: ContractAddress, game_id: felt252, epoch: u32, start_hash: felt252,
    end: Envelope<R::State>, acks: Span<Signature>, os_program: felt252,
);
fn assert_virtual();
fn snapshot<impl R: GameRules>(
    channel: ContractAddress, game_id: felt252,
) -> (Terms<R::Config>, u32, felt252, u64, felt252, u64);
fn payload<impl R: GameRules>(
    class_hash: felt252, prover: felt252, chain_id: felt252, channel: felt252, game_id: felt252,
    context: felt252, epoch: u32, start_hash: felt252, end_hash: felt252,
) -> Array<felt252>;
fn message_hash(prover: felt252, payload: Span<felt252>) -> felt252;
```

| Function | Behavior | Panics |
| --- | --- | --- |
| `execute` | The virtual `__execute__`. Calls `assert_virtual`. With `opening` `None`, reads and checks the snapshot with `state_hash(start)` as the start hash. With `Some(terms)`, for a game no channel has opened yet, reads nothing onchain: it checks the terms as the snapshot's (below), and that `epoch` is 0 and `start` is `open(terms)`. Then replays `batch` with `context_hash(terms)` and sends `payload(own class hash, own address, ..., state_hash(start), state_hash(end))` to L1 address 0. | `assert_virtual`'s; the snapshot checks (`'Unknown channel'` from the channel when `opening` is `None` for a game nobody opened); with `opening`, `'Wrong channel terms'`, `'Wrong chain terms'`, `'Wrong game prover'`, `'Stale proof epoch'` unless epoch 0 and `'Wrong proof anchor'` unless `start` is the opening state; every [replay panic](/reference/cairo#replay). |
| `settle` | The real settlement. Reads and checks the snapshot with `start_hash`, rebuilds the expected payload for `start_hash` to `end`, runs `check_facts` on the transaction's proof facts against `message_hash(own address, payload)`, `os_program`, the current block and the base block, then calls the channel's `accept_verified(game_id, epoch, start_hash, end, acks)`. It has no caller check. | The snapshot checks; any `check_facts` panic; any panic of `accept_verified`. |
| `assert_virtual` | Only a zero-fee virtual `INVOKE_V3` from the OS may run the proving path. | `'Only OS caller'` for a non-zero caller; `'Only invoke v3'` unless the transaction version is 3 (or its query version); `'Nonzero tip'`; `'Nonzero gas price'` if any resource bound has a non-zero `max_price_per_unit`. |
| `snapshot` | Calls the channel's `snapshot(game_id)`: terms, epoch, anchor hash, anchor block, candidate hash and candidate block. | `'Malformed snapshot'` if the result does not deserialize. |
| `payload` | `[class_hash, TAG, 'ARBITER_PROVED_V1', chain_id, prover, channel, game_id, context, epoch, start_hash, end_hash]`: what a proved transition commits to. | |
| `message_hash` | Poseidon of `prover`, `0` and the serialized `payload`: the hash the proof facts carry for `payload` sent by `prover` to L1 address 0. | |

Both `execute` and `settle` check the snapshot the same way: the terms name this channel and game (`'Wrong channel terms'`) and this chain (`'Wrong chain terms'`), `epoch` is the channel's current epoch (`'Stale proof epoch'`), the terms' `prover` is this contract (`'Wrong game prover'`), and the start hash is the anchor's or the candidate's (`'Wrong proof anchor'`). That picks the base block: the anchor block for the anchor, otherwise the candidate block. At epoch 0 the anchor is the opening state, which the terms fix, so a proof from it has no base-block floor: it may be based before the game opened, and `settle` it in the same transaction as `open_game`. A later anchor and any candidate keep the floor. The channel's own `snapshot` panics with `'Unknown channel'` for a game nobody opened, and `'Channel not live'` for a settled one.

### Proof facts

`arbiter_adapter::facts`, re-exported at the crate root.

```cairo
pub const MAX_PROOF_AGE: u64 = 4000;

#[derive(Copy, Drop, Serde)]
pub struct ProofFacts {
    pub proof_version: felt252,
    pub program_variant: felt252,
    pub virtual_program_hash: felt252,
    pub output_version: felt252,
    pub base_block_number: u64,
    pub base_block_hash: felt252,
    pub config_hash: felt252,
    pub messages: Span<felt252>,
}

fn check_facts(encoded: Span<felt252>, expected: felt252, os_program: felt252, current: u64, anchor: u64);
```

`MAX_PROOF_AGE` is the maximum age, in blocks, of a proof's base block at settlement. `check_facts` deserializes network-verified `ProofFacts` and checks, in order, with `anchor` the block the start state was set in (the base block `settle` picks; 0 for the epoch-0 anchor):

| Check | Panic |
| --- | --- |
| `encoded` is not empty | `'Missing proof facts'` |
| It deserializes as `ProofFacts` | `'Malformed proof facts'` |
| Nothing follows | `'Trailing proof facts'` |
| `proof_version` is `'PROOF1'` (the small path) or `'PROOF2'` (the large path added in Starknet v0.14.4) | `'Wrong proof version'` |
| `program_variant` is `'VIRTUAL_SNOS'` | `'Wrong program variant'` |
| `virtual_program_hash` equals `os_program` | `'Wrong OS program'` |
| `output_version` is `'VIRTUAL_SNOS0'` | `'Wrong output version'` |
| `base_block_number >= anchor` | `'Proof predates anchor'` |
| `base_block_number < current` | `'Invalid base block'` |
| `current - base_block_number <= MAX_PROOF_AGE` | `'Expired proof'` |
| `messages` is exactly `[expected]` | `'Wrong proved transition'` |

### The account contract

A game's adapter is a thin `#[starknet::contract(account)]` over these functions. The counter's ([`adapter/examples/counter/src/lib.cairo`](https://github.com/broody/arbiter/blob/main/adapter/examples/counter/src/lib.cairo)) has no admin, upgrade path, arbitrary calls or custody. Its virtual OS program is fixed at deployment, so an OS upgrade needs a new instance. Deploy one instance per Starknet OS program and allow its class in the game's channel with `allow_prover`.

```cairo
#[starknet::contract(account)]
pub mod CounterProver {
    use arbiter::{Batch, Envelope, Signature, Terms};
    use arbiter_adapter::prover;
    use arbiter_counter::{Action, Config, Counter, CounterRules};
    use starknet::storage::{StoragePointerReadAccess, StoragePointerWriteAccess};
    use starknet::{ContractAddress, VALIDATED};

    #[storage]
    struct Storage {
        os_program: felt252,
    }

    #[constructor]
    fn constructor(ref self: ContractState, os_program: felt252) {
        assert(os_program != 0, 'Zero OS program');
        self.os_program.write(os_program);
    }

    #[abi(embed_v0)]
    impl ProverImpl of super::ICounterProver<ContractState> {
        fn settle(
            ref self: ContractState,
            channel: ContractAddress,
            game_id: felt252,
            epoch: u32,
            start_hash: felt252,
            end: Envelope<Counter>,
            acks: Span<Signature>,
        ) {
            prover::settle::<
                CounterRules,
            >(channel, game_id, epoch, start_hash, end, acks, self.os_program.read());
        }

        fn os_program(self: @ContractState) -> felt252 {
            self.os_program.read()
        }
    }

    #[abi(embed_v0)]
    impl VirtualImpl of super::IVirtualCounter<ContractState> {
        fn __validate__(
            self: @ContractState,
            channel: ContractAddress,
            game_id: felt252,
            epoch: u32,
            start: Envelope<Counter>,
            batch: Batch<Action>,
            opening: Option<Terms<Config>>,
        ) -> felt252 {
            prover::assert_virtual();
            VALIDATED
        }

        fn __execute__(
            ref self: ContractState,
            channel: ContractAddress,
            game_id: felt252,
            epoch: u32,
            start: Envelope<Counter>,
            batch: Batch<Action>,
            opening: Option<Terms<Config>>,
        ) {
            prover::execute::<CounterRules>(channel, game_id, epoch, start, (), batch, opening);
        }
    }
}
```
