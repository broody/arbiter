# Add a clock

Clocks are **optional**, and each game opts in. Without a clock, a player who
stops moving can only be pushed by a dispute, which gives them a whole response
window (5 minutes to 7 days) to answer and then forced play onchain. With a
clock, a **referee** keeps time offchain: it stamps every step as it arrives and
flags a seat whose time runs out, so a stall costs the staller the game in
seconds, not days.

Players sign moves; the referee signs time. It can't forge a move or a result.
Its power is over time only, and it's the one party of a timed game that
players must trust to be fair and online. See
[Clocks and the referee](/concepts/clocks) for how charging, stamps and flags
work.

A timed game can also take its randomness from the referee, so that no seat
has to be online to reveal. That is a second opt-in, and a second thing to
trust the referee with: see
[Take randomness from the referee](#take-randomness-from-the-referee).

## Choose a time control

A game's `TimeControl` is part of its terms:

| Field | Meaning |
| --- | --- |
| `referee` | The referee's **public** key. It signs stamps, starts and flags |
| `settings` | The settings of the game's time rules |
| `rng_tip` | Zero (or left out in JS) when the seats reveal randomness to each other, the default. Non-zero to take the game's randomness from the referee: see [Take randomness from the referee](#take-randomness-from-the-referee) |

Most games use the standard time rules (`StandardTime` in Cairo,
`standardTime` in the SDK, the default for a codec without `time`). Their
settings, in milliseconds:

| Setting | Meaning |
| --- | --- |
| `turn_ms` | Time each turn gets first. Unused time doesn't carry over |
| `bank_ms` | Each seat's main time, spent once a turn's `turn_ms` runs out |
| `increment_ms` | Added to a seat's bank when its turn ends |
| `byoyomi` | `null`, or `{ periods, period_ms }`: once its bank is spent, a seat must end each turn within a period. A turn that ends inside a period costs none, each period that runs out is lost, and a seat that outlasts its last period has flagged |

A turn is a run of steps while your game's `due` seat stays the same. A pending
reveal is timed on its own, as a turn of one step for the revealer, so
withholding a reveal burns the revealing seat's clock. A roll the referee owes
is charged to nobody.

| Style | `turn_ms` | `bank_ms` | `increment_ms` | `byoyomi` |
| --- | ---: | ---: | ---: | --- |
| 60 seconds per move, nothing saved (Surround's old per-turn clock) | 60000 | 0 | 0 | `null` |
| Blitz 3+2 | 0 | 180000 | 2000 | `null` |
| Per-turn timer with a small reserve (Hashfront-style) | 90000 | 30000 | 0 | `null` |
| Japanese byo-yomi, 10 min + 5 × 30 s | 0 | 600000 | 0 | `{ periods: 5, period_ms: 30000 }` |

Each setting is at most 30 days (`MAX_CLOCK_MS`), byo-yomi has 1 to 255
periods (`MAX_PERIODS`) of a positive length, and `turn_ms`, `bank_ms` or
byo-yomi must be positive. `create` rejects anything else
(`'Invalid time control'`, `'Invalid byo-yomi'`).

### Time rules

A game with a different notion of time writes its own rules: a Cairo
`referee::clocks::ClockRules` named by `GameRules::Time`, and its JS mirror as
the codec's `time` (see [Mirror the rules in JS](/guide/codec#optional-time-rules)).
The counter's hourglass rules, where the time a seat uses flows to its
opponent, are a complete example in about 40 lines
([`examples/counter/src/hourglass.cairo`](https://github.com/broody/referee/blob/main/examples/counter/src/hourglass.cairo)).
The settings are then whatever those rules define, for instance
`{ bank_ms }` for the hourglass.

## Run a referee

The referee is usually a [keeper](/infra/keeper) started with a referee key:

```json
{
  "referee": { "private_key_env": "KEEPER_REFEREE_KEY", "rng_secret_env": "KEEPER_RNG_SECRET" }
}
```

```bash
KEEPER_PRIVATE_KEY=0x… KEEPER_REFEREE_KEY=0x… KEEPER_RNG_SECRET=0x… node keeper/server.mjs keeper/config.local.json
```

The keeper referees every timed game whose terms name its referee key. It
stamps steps as they arrive, starts a clock that no step started within the
entry's `start_grace_seconds`, flags on a timer, and never stamps two steps at
one seq. `GET /info` shows its referee public key. With the game's Dojo
`world` and `namespace` in its config, it also finds new timed games that name
its key from the channel's `JOINED` events, so they get a referee even if no
seat registers them.

`rng_secret_env` is optional. With a randomness secret the keeper also gives
randomness to the games that ask for it, and `GET /info` shows
`randomness: true`.

:::warning
Use a referee key that is different from the keeper's account key, and from
every seat's session key. `create` and `join` refuse a referee key that equals a
seat's session key (`'Referee is a seat'`).
:::

## Create a timed game

Pass the time control as `create`'s last argument, as Cairo `Option` serialization:
`0` followed by the fields for `Some`, or `1` for an untimed game.

```js
import { encodeTimeControl } from '@referee/sdk'

const clock = { referee: REFEREE_PUBLIC_KEY, settings: { turn_ms: 60000, bank_ms: 0, increment_ms: 0, byoyomi: null } }
await wallet.execute(contractCall(CHANNEL, 'create', [
  20, opponentAddress, publicKey(privateKey), tip, ADAPTER_ADDRESS, 3600,
  0, ...encodeTimeControl(counter, clock),   // Some(TimeControl), encoded with the game's time rules
]))
```

Joining a timed game accepts its referee. The time control is bound into the
context, like every other term.

This `clock` has no `rng_tip`, so the seats reveal randomness to each other.
`join` then takes zeros for the referee's tip and its signature (see
[Build the client](/guide/client#2-open-the-game-onchain)).

## Play a timed game

In a timed game a step counts only once the referee has stamped it, so a seat
can't apply its own step. `store.move` signs and marks the step but doesn't
apply it: it waits in `session.pending`. You submit your pending steps to the
referee and pull them back stamped:

```js
await store.move(session, play({ kind: ADD, amount: 3 }), privateKey) // signed, not applied
await keeper.submit(session, { store })  // the keeper stamps every pending step; pulled back and applied
```

Stamps stay out of the transcript, so within your turn you can sign the next
step before the last one comes back: each `store.move` signs from
`session.tip`, the state after your pending steps.

The other seat's steps, and the referee's `start`, `flag` and rolls, arrive
through `pull` (or `follow`) as usual. Every stamped record carries its `stamp`
(referee time, in milliseconds) and the referee's `attestation`.
`Session.receive` verifies both, and refuses an unstamped step in a timed game.

:::note
`Session.move` throws in a timed game
(`'Timed games apply a step once the referee stamps it: sign, send, then receive'`).
Use `sign` then `receive`, or `store.move` with `keeper.submit`.
:::

### Show the clocks

`timeLeft(game, terms, env, at)` gives each seat's clock at referee time `at`,
as the time rules' `view` shows it. With `standardTime` each seat's entry is
`{ turn, bank, periods, period }`. The due seat's counts the time it has used
since its turn began; the others show what they start their next turn with.
Clients don't know the referee's clock exactly, so estimate it from the last
stamp:

```js
import { timeLeft } from '@referee/sdk'

const receivedAt = Date.now()   // when the latest stamped step arrived
function render() {
  const at = session.env.clock.stamp + (Date.now() - receivedAt)
  const [mine, theirs] = timeLeft(counter, session.terms, session.env, at)
  // mine.turn, mine.bank, mine.periods, mine.period …
}
```

The clock starts at the first stamp, or at the referee's `start`. Until then,
and while it's paused, `env.clock.stamp` is 0 and nobody is charged.

### When time runs out

Once the due seat has used more than its time rules allow, the referee can
**flag**:

- a step from that seat arriving afterwards is refused (`'Flag fell'`);
- the referee appends a `Flag` step, which ends the game with the other seat
  winning and `REASON_TIMEOUT` (129).

A flagged game is a finished game like any other. Anyone can settle it, and a
keeper does so on its own.

## Take randomness from the referee

By default the seats reveal randomness to each other, so every roll waits for
the other seat. A timed game can take its rolls from its referee instead: the
referee reveals as it stamps, and no seat has to be online to reveal.

The referee can't bias a roll, but it knows its own next value ahead of time,
so players trust it not to leak that value (see
[Randomness](/concepts/randomness#what-the-referee-can-and-cant-do)). The
referee must give randomness: a keeper does when it has a randomness secret.

:::steps

### Ask at create

Pass a non-zero `rng_tip` in the time control. Any non-zero value asks. The
game id doesn't exist yet, so the referee's real tip comes at join.

```js
const clock = {
  referee: REFEREE_PUBLIC_KEY,
  settings: { turn_ms: 60000, bank_ms: 0, increment_ms: 0, byoyomi: null },
  rng_tip: 1n,   // ask for the referee's randomness
}
await wallet.execute(contractCall(CHANNEL, 'create', [
  20, opponentAddress, publicKey(privateKey), tip, ADAPTER_ADDRESS, 3600,
  0, ...encodeTimeControl(counter, clock),
]))
```

### Fetch the referee's signed tip

The joining seat asks the keeper for its tip for this game:

```js
const { rng_tip, signature } = await keeper.tip({ channel: CHANNEL, game_id: gameId })
```

The keeper reads the created game from the channel. It answers only if the
game names the keeper's referee key with a non-zero `rng_tip`. The same game
always gets the same tip.

### Join with it

```js
await wallet.execute(contractCall(CHANNEL, 'join', [
  gameId, publicKey(privateKey), tip,
  rng_tip, signature.r, signature.s,   // the referee's tip and its signature
]))
```

`join` checks the signature against the referee's key and puts the tip in the
terms. It refuses a game that asked without a tip (`'Referee tip needed'`), and
a tip the referee didn't sign for this game (`'Invalid session signature'`).
Read the terms back as usual: `terms.clock.rng_tip` is now the referee's tip.

### Play

Send an action that needs a roll as `playRandom` with your next chain value,
as in any game (`nextValue` is from
[Build the client](/guide/client#randomness)). The keeper stamps it and rolls
at once, so two records come back: your stamped step, then the referee's roll.

```js
await store.move(session, playRandom({ kind: GAMBLE, amount: 0 }, nextValue(session, mine.seat, mine)), mine.privateKey)
const records = await keeper.submit(session, { store })   // your stamped step, then the roll
```

No seat sends a `reveal` in such a game. While the referee owes a roll,
`session.due()` is `REFEREE` (254) and neither seat can be flagged.

:::

## Disputes in a timed game

While the referee is live, a dispute doesn't stop the clock. A keeper that
referees the game sends `acknowledge` with the referee's signature as soon as
a dispute opens. When the window passes, `resolve` commits the best candidate
and, if the game isn't finished, returns it to `ACTIVE`, not forced play. Play
goes on offchain, and a staller is flagged there.

## If the referee goes down

Nothing can be stamped, so the game stalls. The fallback is the untimed
channel: a player opens a dispute, the best signed history is submitted, and,
with no acknowledgement from the referee, an unfinished game moves to forced
play onchain. Forced steps carry no stamps, so the clock **pauses** during
forced play, and the channel's windows keep time instead.

When the referee is back, it returns the game from forced play on its own with
`resume_by_referee`: the seats don't need to approve. Its last stamp is then
stale, so it restarts the clock once without charging anyone for the gap: from
the last stamp when the due seat's step comes first, or with a `start` after
the start grace.

A restarted keeper resumes each clock where its last stamp left it, so seats
aren't charged for the referee's own downtime.

### A roll that waits for the referee

In a game that takes its randomness from the referee, no seat can give a roll.
If a seat plays an action that needs one onchain, in forced play, forced play
**pauses**: no seat is due, nobody can be timed out, and the deadline is set 3
days ahead. During the pause:

- anyone who holds the referee's next value posts it with `roll`, and forced
  play goes on with a fresh window for the next seat;
- the referee, once it is back, returns the game with `resume_by_referee` and
  rolls offchain. A keeper does this, and also answers a roll it owed when it
  stopped;
- both seats can sign a void approval, and anyone then calls `void`.

Once the 3 days have passed, anyone may call `void` without approvals. A void
game settles with `REASON_VOID` (131): it has no winner, and it isn't a draw.
[Build the client](/guide/client#5-watch-for-disputes) shows the calls.

## Referee without a keeper

`Referee` in `@referee/sdk` is what the keeper uses. Run it yourself to referee
from your own server:

```js
import { Referee, Session } from '@referee/sdk'

// Keep one Referee per game for as long as the game runs.
const referee = new Referee(new Session(counter, terms), REFEREE_PRIVATE_KEY)

const started = referee.start()                      // the attested start record: the clock runs from here
// … send `started` to both seats

const stamped = referee.stamp(signedStepFromASeat)   // throws 'Flag fell' once time is up
// … send `stamped` to both seats

const deadline = referee.deadline()                  // wall-clock ms when the due seat can be flagged
setTimeout(() => {
  const flagged = referee.flag()                     // the attested Flag record, or null if not yet
  // … send `flagged` to both seats
}, deadline - Date.now())

// During a dispute: the signature `acknowledge` takes.
const ack = referee.acknowledgement(channel.epoch, channel.deadline)
// In forced play: the signature `resume_by_referee` takes.
const resume = referee.resumeSignature(channel.epoch, channel.anchor.hash)
```

Anyone may send `acknowledge(game_id, epoch, signature)` and
`resume_by_referee(game_id, epoch, signature)` to the game's system.

To give a game its randomness too, keep a hash chain for it, sign its tip for
the joining seat, and pass the chain as `rng`:

```js
import { Referee, RngChain, Session, sign, tipHash } from '@referee/sdk'

const chain = new RngChain(CHAIN_SEED, 256)   // long enough for every roll of the game
// The joining seat brings chain.tip and this signature to `join`.
const tipSignature = sign(tipHash(counter, chainId, CHANNEL, gameId, chain.tip), REFEREE_PRIVATE_KEY)

const referee = new Referee(new Session(counter, terms), REFEREE_PRIVATE_KEY, { rng: chain })
const held = referee.session.steps.length
referee.stamp(signedStepFromASeat)                 // rolls at once after a step that asks for randomness
const records = referee.session.steps.slice(held)  // the stamped step, then the roll
// … send the records to both seats, in order
```

`referee.roll()` answers a roll that is already pending, for example after a
restart. See [`Referee`](/reference/sdk#rolls).

Persist `referee.session` as the games go. A `Referee` built from a stored
session resumes its clock at the last stamp.
